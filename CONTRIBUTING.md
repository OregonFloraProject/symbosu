# Contribution Guidelines for OregonFlora

Thanks for your interest in OregonFlora! Bug reports, ideas, docs fixes and pull requests are all welcome. This guide covers everything you need to build the app, find your way around the code and get a change merged.

OregonFlora is maintained by the [OregonFlora team](https://oregonflora.org/pages/contact.php), so please be patient with reviews.

## Contents

- [For developers](#for-developers)
- [For non-developers](#for-non-developers)

## For developers

The master branch will not be edited, unless there is a hotfix needed to be quickly implemented. Otherwise, all forms of contribution need to come from dev branch.

For any new feature, or bugfix big enough to be its own branch, spawn off the dev branch.

Any new branch spawned from dev, when the dev finishes with their development, needs to create a PR (pull request) to merge to dev. The title and description of the PR should be short, concise, understandable. It should note what you did, why and how you did it. Ideally, this PR should be reviewed by an OregonFlora maintainer before merging. The total LOCs of a PR should not exceeded 1000. If it does, there should be an explanation in the PR description on the reason for the large LOC count.

Coding agent usage is fine, so long as the person using it is responsible for its output. If the code output in the PR is verbose, obtuse, we reserve the right to either ask the author to redo the PR or drop the PR.

## For non-developers

For contributors uploading assets (images, maps, PDF documents), you can upload to either `master` or `dev` branch. Be sure to contact the maintainers beforehand as we have to maintain synchronization between the two branches.
